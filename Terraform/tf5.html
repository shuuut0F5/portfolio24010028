Terraform × LXD による複数コンテナ Web インフラ構築

作成者：shuto — ローカル環境でクラウドインフラの基礎を再現したプロジェクト

プロジェクト概要

このプロジェクトでは、Terraform と LXD を用いて、 複数の Ubuntu コンテナを Web サーバーとして構築し、ロードバランサーで束ねるインフラ をローカル環境に構成しました。 AWS の EC2 × Auto Scaling × ELB に相当する構成を、自分の PC 上で再現しています。

ここまでで実現可能になったこと

1. Terraform によるインフラのコード化（IaC）

  • インフラ構成を HCL（Terraform 設定ファイル）で記述し、コードとして管理。
  • terraform apply だけで複数コンテナ環境を自動構築できるようになった。
  • クラウドインフラの考え方（宣言的な構成管理）をローカルで体験・理解。
resource "lxd_container" "web" {
  count = 3
  name  = "web-${count.index + 1}"
  image = "ubuntu:22.04"
}

2. LXD による複数コンテナ管理

  • web-1 / web-2 / web-3 の 3 台の Ubuntu コンテナを自動作成・起動。
  • lxc exec によるコンテナへのログイン、lxc delete による削除など、基本操作を習得。
  • 軽量なコンテナ仮想化技術を使い、仮想マシンより高速な検証環境を構築できるようになった。

3. nginx を用いた複数 Web サーバー構築

  • 各コンテナに nginx をインストールし、Web サーバーとして動作させた。
  • /var/www/html/index.html を編集し、コンテナごとに異なるコンテンツを表示。
  • Web サーバー構成の基本（HTTP サーバー、ドキュメントルート、静的コンテンツ）を理解。
# web-1
echo "This is web-1" | sudo tee /var/www/html/index.html

# web-2
echo "This is web-2" | sudo tee /var/www/html/index.html

# web-3
echo "This is web-3" | sudo tee /var/www/html/index.html

4. ホスト ↔ コンテナ間のネットワーク構成（ポートフォワード）

  • LXD の proxy デバイス機能を用いて、ホストから各コンテナの nginx にアクセス可能にした。
  • localhost:8081 → web-1、8082 → web-2、8083 → web-3 というマッピングを構成。
  • ネットワーク経路・ポートフォワードの概念を実際に設定し、理解を深めた。
lxc config device add web-1 http proxy listen=tcp:0.0.0.0:8081 connect=tcp:127.0.0.1:80
lxc config device add web-2 http proxy listen=tcp:0.0.0.0:8082 connect=tcp:127.0.0.1:80
lxc config device add web-3 http proxy listen=tcp:0.0.0.0:8083 connect=tcp:127.0.0.1:80

5. HAProxy によるロードバランサー構築

  • ホスト側に HAProxy を導入し、3 台の Web サーバーを 1 つの入口で束ねる構成を実装。
  • http://localhost:8080 にアクセスすると、web-1 → web-2 → web-3 にラウンドロビンで振り分け。
  • ロードバランシングの仕組みを実際に構築・検証し、クラウドの ELB に相当する動作を理解。
frontend http_front
    bind *:8080
    mode http
    default_backend http_back

backend http_back
    mode http
    balance roundrobin
    server web1 127.0.0.1:8081 check
    server web2 127.0.0.1:8082 check
    server web3 127.0.0.1:8083 check

curl http://localhost:8080
# → This is web-1
# → This is web-2
# → This is web-3（リロードで切り替わる）

改善できたこと・成長したポイント

1. 手作業のインフラ構築から、再現性の高い IaC へ

  • 以前は「1 台ずつ手動で環境構築」する必要があったが、今はコードで一括構築が可能。
  • 環境の再現性が高まり、「壊してもすぐ作り直せる」開発スタイルを実現。
  • インフラ構成の変更もコード差分として管理できるようになり、品質が向上。

2. 複数コンテナの管理とスケールアウトの基礎を習得

  • count を変更するだけでコンテナ数を増減できる構成を理解。
  • 単一サーバー構成から、複数サーバー構成への移行を自力で設計・実装。
  • クラウドの「スケールアウト」の考え方を、ローカル環境で体験できるようになった。

3. ネットワーク設計の理解が深まり、ホストとコンテナの通信を設計できるようになった

  • ポートフォワードやプロキシ設定を通じて、通信経路を意識した構成が組めるようになった。
  • Web サーバーへのアクセス経路を自分で設計し、問題があれば原因を追えるようになった。

4. ロードバランサーを用いた本番に近い構成を理解・構築

  • 複数 Web サーバーを 1 つの入口で束ねる構成を、自分の手で作り上げた。
  • 負荷分散の挙動（ラウンドロビン）を実際に確認し、理論だけでなく動作として理解。
  • クラウドインフラの基礎（EC2 × ELB）をローカルで再現できるレベルに到達。

5. クラウドインフラの基礎を、自分の PC 上で再現できるようになった

  • 仮想化・コンテナ・Web サーバー・ロードバランサー・IaC といった要素を一通り経験。
  • 「クラウドで動いている仕組み」を、ローカルで具体的にイメージできるようになった。
  • インフラエンジニアとしての基礎力が、実践レベルまで引き上がったと感じている。
